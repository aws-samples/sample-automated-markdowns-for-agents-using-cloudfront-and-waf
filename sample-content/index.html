Automated Format Conversion for AI Agents

Serve AI-agent-optimized content at the edge. Amazon CloudFront + AWS WAF detect AI bot requests that accept markdown and automatically convert HTML — with YAML frontmatter and metadata headers.

Get Started Architecture

The Problem

AI coding agents (Claude, GPT, Copilot) increasingly crawl documentation sites to assist developers. These agents consume HTML pages but work far more effectively with clean markdown. Pre-generating every format for every page is wasteful. Most pages may never be requested by an AI agent.

Key Insight: Instead of pre-generating every possible content format, detect what's needed at the edge, serve the original, and asynchronously generate the optimized format. On the next request, serve it directly — with metadata that helps AI agents estimate context window usage.

How It Works

Step Component Action
1 AWS WAF Bot Control V5 Detects AI bot and Accept: text/markdown header, injects x-amzn-waf-format-convert-needed: markdown
2 CloudFront Function + KVS Checks KVS for existing format marker. If found, creates dynamic origin group and rewrites URI to /formats/markdown/...
3 Dynamic Origin Group Tries Formats Amazon S3 bucket first. Falls back to Format-Missing Distribution (protected by origin-verify AWS WAF) on 403
4 Generation Pipeline CFF logs trigger async pipeline: SQS FIFO → Lambda (turndown + metadata extraction) → S3 + DynamoDB → KVS

Four Request Paths

Scenario Flow Latency
Non-bot (browser) AWS WAF → CFF (pass through) → Content S3 → 200 Direct, zero failover
Bot, no KVS marker AWS WAF → CFF (logs format_needed) → Content S3 → 200 Direct, triggers async generation
Bot, KVS hit + S3 exists AWS WAF → CFF (dynamic origin group + rewrite) → Formats S3 → 200 Direct, zero failover
Bot, KVS hit + S3 missing AWS WAF → CFF (dynamic origin group + rewrite) → Formats S3 (403) → Format-Missing Distro → Content S3 → 200 One failover, triggers regeneration

Key Design Decisions

Content Negotiation

AWS WAF requires both AI bot detection and Accept: text/markdown. Only bots that explicitly request markdown trigger conversion. Vary: Accept ensures proper caching.

Dynamic Origin Groups

CFF uses cf.createRequestOriginGroup() to create per-request origin groups. No static origin group configuration needed — routing is entirely driven by KVS markers.

DDB → KVS Sync

DynamoDB as durable marker store, streamed to CloudFront KVS with batchSize: 1 for strict ordering. No ETag concurrency issues.

Metadata & Frontmatter

Generated markdown includes YAML frontmatter (title, description, token count) and S3 x-amz-meta-* headers for programmatic access by AI agents.

Quick Deploy

git clone https://github.com/aws-samples/sample-automated-markdowns-for-agents-using-cloudfront-and-waf.git
cd sample-automated-markdowns-for-agents-using-cloudfront-and-waf
npm install
npx cdk deploy --profile your-profile

The stack deploys to us-east-1 (required for Amazon CloudFront AWS WAF). See the Getting Started guide for full deployment and testing instructions.

Technology Stack

  • AWS CDK v2 — Infrastructure as Code (TypeScript)
  • Amazon CloudFront — Content delivery with 2-distribution chain
  • AWS WAF Bot Control V5 — AI bot classification + Accept header matching
  • CloudFront Functions — Sub-millisecond routing with dynamic origin groups
  • CloudFront KeyValueStore — Edge-local marker lookups
  • Lambda + SQS FIFO — Async format generation pipeline
  • DynamoDB Streams — CDC to sync markers to KVS
  • Turndown — HTML-to-markdown conversion with GFM support + metadata extraction
