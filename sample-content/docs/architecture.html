Edge Layer (AWS WAF + CFF + KVS)

The edge layer handles bot classification, content negotiation, routing decisions, and signal emission — all at CloudFront edge locations with sub-millisecond latency. Built from modular CDK constructs: BotControlWaf, RoutingFunctions, OriginVerifyWaf, and FormatMissingDistribution.

AWS WAF WebACL (Bot Control)

A single WebACL with three rules, evaluated in priority order:

Rule Priority Type Action
AWSBotControl 0 Managed Rule Group (Bot Control V5, COMMON) Count (applies labels)
FormatConvertHeaderInjection 1 AND: Label Match (bot:category:ai) + ByteMatch (Accept contains text/markdown) Count + inject x-amzn-waf-format-convert-needed: markdown
DoNotConvert 2 Regex Pattern Set (URI match) Count + inject x-amzn-waf-no-convert: true

Content Negotiation: The FormatConvertHeaderInjection rule uses an AND statement — both the AI bot label and Accept: text/markdown must be present. This prevents unnecessary format generation for bots that don't explicitly request markdown (e.g., search crawlers).

AWS WAF WebACL (Origin Verify)

A second WebACL protects the Format-Missing distribution from direct internet access. It defaults to Block and only allows requests containing a shared secret in the x-origin-verify header. This secret is generated at deploy time and injected as a custom origin header by the Primary distribution.

CloudFront KeyValueStore (KVS)

Stores URI → marker mappings for sub-millisecond lookups in the CFF. Markers are JSON objects:

{
  "action": "rewrite",
  "path": "/formats/markdown/blog/getting-started.html",
  "format": "markdown",
  "ttl": 1710000000,
  "headers": {
    "title": "Getting Started",
    "tokens": "1234"
  }
}

The headers field carries metadata extracted during generation, available for future CFF-level response header injection.

2-Distribution Chain

Two CloudFront distributions work together to handle all four request paths without Lambda@Edge:

Primary Distribution

Property Value
AWS WAF Bot Control WebACL attached
CFF Viewer Request — bot detection + KVS routing + dynamic origin groups
Default Origin Content S3 (non-bot traffic goes here directly)
/static/* Content S3 direct (no CFF, aggressive caching)
Response Headers Vary: Accept for content negotiation caching

Format-Missing Distribution

Property Value
AWS WAF Origin-Verify WebACL (blocks all except requests with shared secret header)
CFF Viewer Request — strips /formats/<format>/ prefix, logs object_missing
Default Origin Content S3 (serves original HTML as fallback)

Why Two Distributions?

The Primary CFF uses cf.createRequestOriginGroup() to dynamically create an origin group per request when a KVS marker is found. This routes bot requests to Formats S3 first, with automatic failover to the Format-Missing distribution on 403. Non-bot requests bypass this entirely and go directly to Content S3.

  1. Non-bot: URI unchanged → Content S3 resolves immediately (zero failover)
  2. Bot with marker: CFF creates dynamic origin group → Formats S3 (200) or failover to Format-Missing Distro (strips prefix, serves original)
  3. Bot without marker: CFF logs format_needed → Content S3 (200), async pipeline generates format

Generation Pipeline

An asynchronous serverless pipeline that converts HTML to markdown on demand:

Component Role Key Config
CloudWatch Logs Subscription Filters Route CFF log events matching format_needed or object_missing Attached to both CFF log groups
Parser Lambda Decode base64+gzip CW log events, extract signals, send to SQS Node.js 22, 30s timeout
SQS FIFO Queue Deduplication and ordering MessageDeduplicationId = URI (explicit), 5-min dedup window
Generator Lambda Fetch HTML via CloudFront, convert with turndown, extract metadata, add frontmatter, write S3 + DynamoDB NodejsFunction, 512MB, 2min timeout, esbuild bundles turndown

Generator Lambda Details

The Generator Lambda uses turndown with the GFM plugin for high-quality HTML-to-markdown conversion:

import TurndownService from 'turndown';
import { gfm } from 'turndown-plugin-gfm';

const turndown = new TurndownService({
  headingStyle: 'atx',
  codeBlockStyle: 'fenced',
});
turndown.use(gfm);

The Lambda fetches HTML through the Primary CloudFront distribution (not S3 directly) using an x-internal-skip-conversion header to bypass CFF routing. This benefits from CloudFront edge caching.

Metadata & Frontmatter

The Generator Lambda extracts metadata from the source HTML and propagates it through the entire system:

Extraction

Metadata is parsed from HTML <head> elements:

Field Source Example
title <title> tag Getting Started - CloudFront AI Format Converter
description <meta name="description"> Deploy and test the solution...
image <meta property="og:image"> https://example.com/img.png
source_url <link rel="canonical"> https://example.com/docs/intro
tokens Computed (word count × 1.3) 1234

Propagation

  1. YAML Frontmatter: Prepended to the markdown content between --- delimiters
  2. S3 Object Metadata: Stored as x-amz-meta-* headers on the S3 object, returned in HTTP responses
  3. DynamoDB Marker: Serialized as JSON in the headers field, synced to KVS for future CFF use

Example Response

HTTP/2 200
content-type: text/markdown; charset=utf-8
x-amz-meta-title: Getting Started
x-amz-meta-description: Deploy and test the solution
x-amz-meta-tokens: 1234
vary: Accept

---
title: Getting Started
description: Deploy and test the solution
tokens: 1234
---

DynamoDB → KVS Sync

Instead of writing to KVS directly from the Generator Lambda (which suffers from ETag concurrency issues), markers flow through DynamoDB:

  1. Generator Lambda writes marker to DynamoDB (no concurrency issues), including metadata in the headers field
  2. DynamoDB Stream captures the change event
  3. KVS Sync Lambda (batchSize: 1) reads the stream, calls DescribeKeyValueStore for current ETag, then PutKey with the full marker (including headers)

The batchSize: 1 setting guarantees strict sequential processing — no concurrent ETag conflicts. This follows the CDC (Change Data Capture) pattern.

Cleanup on TTL Expiry

When DynamoDB removes a marker via TTL, the KVS Sync Lambda also:

  • Deletes the KVS key (so CFF stops routing to the stale format)
  • Deletes the format file from the Formats S3 bucket

DynamoDB Table Schema

Attribute Type Role
uri String (Partition Key) Original request URI (e.g., /blog/getting-started.html)
action String rewrite
path String Rewritten URI path in Formats S3
format String Target format (e.g., markdown)
headers String (JSON) Serialized metadata (title, description, tokens)
ttl Number Unix timestamp for automatic expiry

CFF: Viewer Request Logic

The primary CloudFront Function runs on every viewer request and makes routing decisions in this order:

  1. If x-internal-skip-conversion header present → pass through (Generator Lambda fetching HTML)
  2. If x-amzn-waf-no-convert header present → pass through (do-not-convert path)
  3. If x-amzn-waf-format-convert-needed header absent → pass through (not an AI bot requesting markdown)
  4. AI bot with markdown Accept detected → read format from header value → KVS lookup:
    • Marker found, valid TTL: Create dynamic origin group via cf.createRequestOriginGroup(), rewrite URI to marker.path, log format_served
    • Marker found, expired TTL: Pass through, log format_needed (triggers regeneration)
    • No marker: Pass through, log format_needed (triggers first-time generation)

Constants like header names, origin IDs, and signal names are injected at CDK synth time via {{PLACEHOLDER}} template substitution — the CFF code itself is generic and reusable.

CFF: Format-Missing Logic

The Format-Missing CFF runs on the second distribution (protected by the origin-verify AWS WAF). It handles requests that failed over from the dynamic origin group:

  1. Match URI against /formats/<format>/ pattern
  2. Extract format name and original path
  3. Strip the /formats/<format>/ prefix from URI
  4. Log object_missing signal with format and original URI
  5. Serve original content from Content S3

Generator Lambda

The Generator Lambda is packaged using CDK's NodejsFunction which automatically bundles turndown and turndown-plugin-gfm via esbuild — no Docker or Lambda Layers required.

Conversion Flow

  1. Receive SQS message with uri and format
  2. Fetch HTML from https://{DISTRIBUTION_DOMAIN}{uri} with x-internal-skip-conversion header
  3. Extract metadata from HTML <head> (title, description, og:image, canonical URL)
  4. Convert HTML body to markdown using turndown (ATX headings, fenced code blocks, GFM tables)
  5. Prepend YAML frontmatter with metadata + computed token count
  6. Write markdown to Formats S3 at formats/{format}{uri} with Content-Type: text/markdown; charset=utf-8 and metadata as S3 object metadata
  7. Write marker to DynamoDB with TTL = now + FORMAT_TTL_SECONDS, including headers field with serialized metadata
