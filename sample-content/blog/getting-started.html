Getting Started

Deploy and test the automated format conversion solution in under 15 minutes.

Prerequisites

  • AWS account with AWS Cloud Development Kit (AWS CDK) bootstrapped in us-east-1
  • Node.js 18 or later
  • AWS Command Line Interface (AWS CLI) configured with a profile that has admin access to the target account
  • Basic familiarity with Amazon CloudFront and AWS CDK (recommended but not required)

Note: The entire stack deploys to us-east-1 because AWS WAF WebACLs for Amazon CloudFront must be created in that region. A single-region stack avoids cross-region complexity.

Deploy the Stack

Clone the repository and deploy:

git clone https://github.com/aws-samples/sample-automated-markdowns-for-agents-using-cloudfront-and-waf.git
cd sample-automated-markdowns-for-agents-using-cloudfront-and-waf

# Install dependencies
npm install

# Preview what will be created
npx cdk diff --profile your-profile

# Deploy (takes ~5 minutes for CloudFront distributions)
npx cdk deploy --profile your-profile

After deployment, AWS CDK outputs the CloudFront distribution domain:

Outputs:
MarkdownGenerationStack.DistributionDomainName = d1234abcdef.cloudfront.net
MarkdownGenerationStack.ContentBucketName = markdowngenerationstack-content-xxxxx
MarkdownGenerationStack.FormatsBucketName = markdowngenerationstack-formats-xxxxx

Save the distribution domain for testing:

export CF_DOMAIN="d1234abcdef.cloudfront.net"

Test: Non-Bot Request

A regular browser request should return the original HTML content directly from the Content Amazon Simple Storage Service (Amazon S3) bucket. No failover, no format conversion.

# Returns HTML (your browser User-Agent is not classified as AI bot)
curl -s "https://$CF_DOMAIN/index.html" | head -5

Expected output:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" ...

Test: AI Bot Request

AWS WAF Bot Control V5 classifies requests based on its own intelligence. Format conversion requires both an AI bot User-Agent and an Accept header that includes text/markdown:

# First request: AWS WAF detects AI bot + Accept: text/markdown
# Injects x-amzn-waf-format-convert-needed header
# Returns original HTML (format hasn't been generated yet)
curl -s -H "User-Agent: GPTBot/1.0" -H "Accept: text/markdown, text/html" \
  "https://$CF_DOMAIN/blog/getting-started.html" | head -5

On the first request, the Amazon CloudFront Function:

  1. Reads the x-amzn-waf-format-convert-needed header (value: markdown)
  2. Looks up the URI in KVS — no marker found
  3. Logs a format_needed signal via console.log()
  4. Serves the original HTML content from Content S3

Why Accept header? Not all AI bots need markdown. The Accept: text/markdown requirement ensures only bots that explicitly request it trigger conversion — preventing unnecessary generation for search crawlers or bots that prefer HTML.

Verify the Generation Pipeline

The format_needed signal triggers the async generation pipeline. Monitor it through CloudWatch:

Check CFF Logs

# View format_needed signals from the primary CFF
aws logs filter-log-events \
  --log-group-name "/aws/cloudfront/function/viewer-request-MarkdownGeneration..." \
  --filter-pattern "format_needed" \
  --profile your-profile

Check SQS Queue

# Messages should appear briefly then be consumed by the Generator Lambda
aws sqs get-queue-attributes \
  --queue-url "https://sqs.us-east-1.amazonaws.com/ACCOUNT/MarkdownGeneration...fifo" \
  --attribute-names ApproximateNumberOfMessages \
  --profile your-profile

Check Generator Lambda Logs

# Look for successful conversion entries
aws logs filter-log-events \
  --log-group-name "/aws/lambda/MarkdownGenerationStack-GeneratorFunction..." \
  --filter-pattern "GenerationSuccess" \
  --profile your-profile

Verify Formats S3 Bucket

# Generated markdown should appear under formats/markdown/
aws s3 ls "s3://$FORMATS_BUCKET/formats/markdown/" --recursive --profile your-profile

Verify DynamoDB Marker

# Marker should exist with action=rewrite
aws dynamodb scan \
  --table-name "MarkdownGenerationStack-MarkersTable..." \
  --profile your-profile

Test: Markdown Response

After ~30 seconds (pipeline processing + KVS sync), repeat the AI bot request:

# Second request: KVS marker exists, CFF creates dynamic origin group and rewrites URI
# Returns generated markdown with frontmatter instead of HTML
curl -s -D - -H "User-Agent: GPTBot/1.0" -H "Accept: text/markdown, text/html" \
  "https://$CF_DOMAIN/blog/getting-started.html"

Expected response headers and body:

HTTP/2 200
content-type: text/markdown; charset=utf-8
x-amz-meta-title: Getting Started - CloudFront AI Format Converter
x-amz-meta-tokens: 1234
vary: Accept

---
title: Getting Started - CloudFront AI Format Converter
description: Deploy and test the automated format conversion solution...
tokens: 1234
---

What Happened

Step Component Action
1 AWS WAF Detected AI bot + Accept: text/markdown, injected x-amzn-waf-format-convert-needed: markdown
2 CFF Found KVS marker, created dynamic origin group via cf.createRequestOriginGroup(), rewrote URI to /formats/markdown/blog/getting-started.html
3 Formats S3 Served markdown content with Content-Type: text/markdown; charset=utf-8 and metadata headers

Configure Do-Not-Convert Paths

Some paths should never be converted (static assets, admin pages). These are managed via an AWS WAF Regex Pattern Set — no code changes needed:

# View current patterns
aws wafv2 list-regex-pattern-sets --scope CLOUDFRONT --profile your-profile

# Update patterns (add /admin/* exclusion)
aws wafv2 update-regex-pattern-set \
  --name DoNotConvertPatterns \
  --scope CLOUDFRONT \
  --id "PATTERN_SET_ID" \
  --lock-token "LOCK_TOKEN" \
  --regular-expression-list \
    RegexString='/static/.*' \
    RegexString='/admin/.*' \
  --profile your-profile

The default deployment excludes /static/* paths. When a request matches these patterns, AWS WAF injects a x-amzn-waf-no-convert header, and the CFF passes the request through without any KVS lookup or URI rewriting.

Clean Up

Remove all deployed resources:

npx cdk destroy --profile your-profile

This deletes both Amazon S3 buckets (content + formats), all CloudFront distributions, AWS WAF WebACLs, Amazon DynamoDB table, AWS Lambda functions, and Amazon SQS queues. The removalPolicy: DESTROY setting ensures clean teardown.
